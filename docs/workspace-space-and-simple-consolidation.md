# Workspace space and simple consolidation / 工作区减负与简易合并

## Screen space

Company navigation defaults to 260 CSS pixels; a stored explicit width remains respected. At 761–1100px the navigation becomes a temporary drawer, closed after selecting a record, without overwriting the wide-screen preference. Outstanding items use a right-side overlay below 1600px rather than reducing the central canvas. Fresh profiles start with it folded; an explicit wide-screen preference remains respected.

The title and group tabs no longer stack as sticky layers over working content. Quick update is a compact toolbar; editing still exposes full-size fields, and notes expand on demand. Group search/filter controls and explanatory text are disclosures, not permanent blocks above the records. Active filters remain visible and can be cleared. Business text is not shortened in storage or translated.

## Consolidation mode

Each holding-company annual engagement can select Full mode or Simple mode. Existing records remain full mode. Switching to simple mode explicitly explains that the project's completion depends only on its own consolidation nodes and their conditions, not component readiness. Empty workflows do not become complete. A valid old holding record without consolidation configuration can explicitly initialize an empty local workflow; no scope or completion is inferred. This is workflow tracking, never audit sign-off.

Switching does not delete components, historical snapshots, condition checks or other annual work. Returning to full mode restores those requirements. The optional `consolidation.mode` field is serialized in the existing V11 envelope; the default full field is omitted so unchanged old records remain unchanged. Use an updated app for these backups: older clients do not implement simple-mode semantics.

The group screen, navigation, portfolio and current-record report use the same completion calculation. A completed simple child contributes one ready unit to a full parent. Full-mode component report readiness requires a live, unarchived source and matching complete reporting periods, not merely checked boxes.

## Historical scope and outstanding items

Active group screens initially fold archived and missing-source components into a counted History disclosure. Missing sources are not described as merely archived. This is a view change only: full-mode readiness is not relaxed. Archived sources remain read-only. A retained unresolved component may still block full-mode completion; explicit scope review, not hiding the row, decides membership.

The outstanding badge and opened list use the same source set: one project, the selected group, one company's annual work, or the active workspace. Simple mode shows the group's own items; its children's records remain available in their projects and global lists. Lists group by source identity and reporting period, not company name alone. Opening the centre resets stale filtering. No cross-client follow-up draft is generated by an aggregate list.

## Verification and limits

Automated checks cover wide/narrow layouts, temporary panel preferences, filter clearing, source navigation, model and browser completion, return to full mode, unchanged historical scope, archived read-only records, and an actual exported backup restored in a clean browser. Existing editing, persistence, date, file-conflict, keyboard, three-language, accessibility and lifecycle suites remain part of release verification; production builds are checked separately.

Layout measurements use identical fictional data and CSS viewport sizes, not human task-time estimates or every native device. Real customer workspaces are not inspected or repaired. Save and keep a backup before updating; unsubmitted form drafts are not part of a business backup. Never clear website data as an update step.
